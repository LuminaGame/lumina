# lumina_editor_api

`lumina_editor_api` is the small contract package between Lumina Studio and its plugins. It depends only on `lumina`, so plugins can be built without depending on the editor app itself.

## Place in the architecture

The editor, `lumina_ui`, implements the API; plugins consume it. Both depend on `lumina_editor_api`, and `lumina_editor_api` depends only on `lumina` (and `shadcn_flutter` for icons and widgets). This keeps the pub dependency graph acyclic: a plugin never has to depend on the editor app. Plugins generated by the New Plugin wizard depend on this package too. See [Editor plugins](../plugins/index.md) for how plugins are discovered, enabled and compiled in.

## Contents of the package

- `lib/src/api_types.dart`: `LuminaEditorPlugin`, `LuminaEditorContext` and every extension type a plugin can register.
- `lib/src/editor_command.dart`: `EditorCommand`, the action behind menu items and toolbar buttons.
- `lib/src/editor_slot_button.dart`, `lib/src/editor_panels.dart`: slot buttons with live state, and opening and observing plugin panels.
- `lib/src/editor_level.dart`: the open level as plugins see it (`EditorLevelAccess`, `LuminaEditorHostContext`).
- `lib/src/editor_theme.dart`: read-only access to the editor's colour theme.
- `lib/src/plugin_storage.dart`, `lib/src/project_settings_section.dart`: per-plugin JSON storage and Project Settings pages.
- `lib/src/mcp/`: the MCP tool, schema, risk and approval types and `EditorMcp`.
- `lib/src/process/`: plugins that run in their own process: `LuminaPluginProcess`, `PluginProcessContext`, `runPluginProcessMain`, the level proxy, `PluginProcessAdapter`, and the shell's `PluginProcessChannel`.
